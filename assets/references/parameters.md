# 参数与判据

配套 `SKILL.md`。这里解释每个数字**为什么**是这个值，以及改错了会怎样。数字可以改，理由不能丢。

## 变调（半音）

```
变调 = 12 × log2(目标音色基频中位数 / 原唱基频中位数)
```

- 量的是**中位数**，不是平均：平均会被长音和换气拉偏。
- 只在「有唱词」的片段量。前奏、间奏、纯伴奏段会污染结果。
- 人对 1 个半音的偏差就开始不适，对 2 个半音会明显跑调。所以取整后仍要试听。

这个数只描述两个片段的典型音高差。说话参考和歌声的音域不同，不能直接当成模型最佳移调。第一次用 0，听完再改。

比值接近 0.5 / 1.5 / 2.0 时要复核：可能是谐波锁定，也可能两段本来就差这么多。

## index_rate（特征检索占比）

这是检索强度，不是音质分数。下表是试听起点，不是实测曲线；同一片段对比后再改。

| 值 | 效果 |
|---|---|
| 0 ~ 0.2 | 细节丢失、发闷、糊成一团 |
| **0.3 ~ 0.5** | 正常区间：既保留音色细节，也不引入检索噪声 |
| 0.6 ~ 0.8 | 开始出现电流感、金属毛刺 |
| > 0.8 | 明显电音 |

检索库（`.index`）质量差时，低一点的 `index_rate` 反而更干净。

## f0 提取算法

| 算法 | 适用 |
|---|---|
| **rmvpe** | 默认。专为复调音乐里的人声设计，中文流行歌首选 |
| **fcpe** | 更快；rmvpe 出现音高台阶（哑音、破音）时换它 |
| crepe | 精度尚可但慢，显存与时间开销高 |
| harvest | 老算法，容易在气声段抖动，不推荐 |
| pm | 最轻，质量最低 |

判断「f0 有没有问题」的方法：看音高曲线在长音上是否是一段一段的台阶。台阶 = 提取错误，不是歌手的问题。

## volume_envelope（音量包络）

当前 Applio 参数是 `--volume-envelope`，不是 `--rms-mix-rate`。0 更接近原录音包络，1 保留转换后的包络。0.25 是起点，不是测量结果。

## protect（清辅音保护）

当前引擎中，低于 0.5 才启用保护，0.5 关闭；数值越低，保护越强。0.33 只是起点。齿音或发闷时，和 0.5 做同一片段对比，不要只往一个方向拧。

## 分离

分离和长音频换嗓都可能显存不足。先看报错来自哪一步，再缩短片段。

| 模型档 | 显存 | 质量 |
|---|---|---|
| Demucs htdemucs（默认参数） | ~7GB | 中，官方说最低 3GB，但默认 segment 就要 7GB |
| Demucs `--segment 6` | 降下来了 | 中，速度变慢 |
| MDX-Net / UVR 系（ONNX） | 2~3GB | 中高，比 Demucs 轻得多 |
| BS-RoFormer / Mel-Band RoFormer | 视 segment 而定 | 最高（SDR 10.8~11.0），建议上云 |

**注意**：RoFormer 系**代码是 MIT，权重不一定**。UVR 生态里大量权重是 CC-BY-NC，商业用途要逐个核对。

## 混音电平

- 人声和伴奏该按发声段对齐。`mix.ps1` 目前只给人声轨加 2dB，没有测量人声减伴奏的差值。
- 响度目标是 **−14 LUFS / −1 dBTP**。脚本编码后再回读；偏差超过 1.5 LU 或 true peak 超限时只告警，不能把告警写成已达标。

## 去"塑料感"的动作，按性价比排序

1. **换技术线**：SVS → SVC（质变）。其余都是微调。
2. **源素材**：目标音色参考决定上限。带 BGM、带混响、带别人声音的参考，换出来会一路带着。
3. **index_rate 0.3~0.5**。
4. **f0 修台阶**。
5. **ckpt merge**：2~3 个相邻 epoch 混合（自己训过才有），能压掉单模型的合成器味。
6. **混音链**：
   - 高通 80~100Hz
   - 200~400Hz +1~2dB 补厚度（治"薄"最直接）
   - 6~9kHz de-ess
   - 轻饱和 / 磁带，加谐波填"空心"
   - 压缩 2:1~3:1，attack 20~30ms
   - 板式混响 1.0~1.5s、pre-delay 20~30ms、湿声 −12dB（空间感是去塑料性价比最高的一步）
   - 双轨 detune ±8 cents + 25ms 延迟，去掉单薄感

## 说话与唱歌的一致性

先用同一个 RVC 推理模型转换说话和唱歌。匹配 EQ 会掩盖差异，放在这个对照通过之后。GPT-SoVITS 是另一条可选路线，不是第一次验证的前提。

## 度量与判断的分界

机器能给的：变调量、时长差、响度、SDR/SI-SNR。
机器给不了的：**像不像、好不好听**。声纹相似度只测前者，后者只能人耳。

任何报告里都要把这两类分开写，不要用分数替代试听。
